# Reader Sync Player 2.1.1.2：纯英 MP4 修复

## 诊断结论

测试文件 `S01E01.eng.mp4` 的实际媒体格式是：

- 容器：MP4
- 视频：MPEG-4 Part 2，sample entry 为 `mp4v`，1280×720
- 音频：AAC-LC，5.1 声道
- 字幕：没有独立字幕轨道；英文字幕已经压在视频画面里
- MP4 元数据：`moov` 位于约 373 MB 文件的末尾

Chrome 不能稳定直接播放 MP4 容器里的 `mp4v` 视频。原扩展还把文件头和文件尾分别当成完整 MP4 解析，因此无法把开头的 `ftyp` 与末尾的 `moov` 组合起来，随后会退回到把整部视频写入浏览器 FFmpeg 内存，造成检测进度长时间不动。

## 本副本的修改

1. 联合读取 MP4 文件头的 `ftyp` 和文件尾的 `moov`，无需先把完整视频写入 FFmpeg 就能检测真实轨道。
2. 对 `mp4v` 等 Chrome 不兼容的视频编码，转为兼容性更好的 H.264/AVC（`avc1`）。
3. 保留原 AAC 音频；不改动 reader 页面通信、台本匹配、字幕解析、播放跟随等逻辑。
4. 修正兼容性判断：MP4 + H.264 + AAC 可以直接播放，不再误判为必须转 HEVC。

## 安装和使用

1. 打开 Chrome 的 `chrome://extensions/`。
2. 开启“开发者模式”。
3. 如果旧版仍启用，先把旧版关闭，避免两个扩展同时响应。
4. 点击“加载已解压的扩展程序”，选择本文件夹。
5. 在 Reader 页面导入纯英版 MP4。检测应很快显示 `mp4v 1280x720` 和 `mp4a`。
6. 点击“一键处理并播放”。不要选择“风险试播原文件”，因为 Chrome 不能直接解码 `mp4v`。

浏览器内首次转码仍需要时间，期间请保持扩展播放器页面打开。现在使用 H.264 的 `ultrafast` 方案，速度和浏览器兼容性都会明显好于原来的 HEVC 方案。
