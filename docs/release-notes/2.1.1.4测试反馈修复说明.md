# Reader Sync Player 2.1.1.4 测试反馈修复

本版本保留 `2.1.1.3`，在独立副本中修复“纯英版加载慢”和“预处理没有正常启动”。

## 已确认的原因

1. `2.1.1.3` 建立媒体库时，即使关闭预处理，也会读取全部视频的媒体头。以当前 72 个视频估算，旧逻辑会额外读取约 1 GB 以上的数据，所以配置文件夹可能比旧版处理单集更慢。
2. 预处理默认关闭；勾选开关后只保存设置，不会立即启动扫描。
3. 批量处理按目录顺序执行，没有优先处理 Reader 当前集。即使当前只想播放 S01E01，也可能等待前面的多集检测或转码。
4. 已生成的 `ReaderSync-Processed` 文件主要依赖浏览器索引记录。重新安装或换版本后，可能无法重新发现磁盘缓存。

## 2.1.1.4 的改动

- 快速建库只读取文件名、大小和修改时间，不读取视频内容。
- 预处理默认开启；从关闭切到开启时会立即开始，不再要求额外点击“重新扫描”。
- 当前 Reader 剧集在队列中永远排第一。
- 当前集预处理完成后立即载入；剩余剧集继续显示后台进度，不再阻塞当前集。
- 命中预处理文件后直接载入，跳过重复 FFmpeg 探测。
- 扫描 `ReaderSync-Processed` 目录，重新安装/更新后可按文件标识发现已有缓存；只有缓存不早于源文件时才复用。
- 单集预处理失败不会终止全部队列，会记录失败数量并继续下一集；当前集失败时仍可回退到原文件流程。
- 源文件大小或修改时间变化后自动废弃旧索引，避免使用过期缓存。

## 第一次测试建议

1. 在 Chrome 扩展页面关闭旧版，只启用 `2.1.1.4`。
2. 打开 Reader 的 S01E01 页面，再选择老友记资源总文件夹。
3. 保持“纯英版”和“优先处理当前集，再后台预处理其余剧集”为选中状态。
4. 状态应先显示当前 S01E01 检测/预处理；当前集完成后会显示“当前集已就绪”，此时即可使用，不必等待全部剧集。
5. 第二次进入相同剧集时，应显示“已命中预处理缓存，跳过重复检测”，加载明显快于首次。

纯英源视频为 `mp4v`，第一次仍必须完整转码为 H.264，这是无法省略的一次性成本；本次修复消除的是全库无效读取、排队等待和缓存重复检测。首次转码完成后的后续加载才是主要加速点。

## 验证结果

- 快速建库回归测试：模拟 72 个视频，只读取 72 次文件 metadata，读取视频内容 0 次。
- 当前集优先、预处理默认启用、开关立即启动、缓存直载路径均有回归检查。
- 当前真实目录的 72 个文件名全部匹配。
- 真实纯英 MP4 与真实无字幕 MKV 探测测试继续通过。
- `player.js` 语法检查通过。
